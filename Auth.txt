1. SYSTEM OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
BrandBattle implements a dual-layer authentication architecture combining a high-performance,
Awwwards-inspired Next.js frontend UI with an enterprise-grade FastAPI + SQLAlchemy + JWT 
backend security system.

Key Security Pillars:
- Passwords hashed using bcrypt salted hashes (never stored in plaintext).
- Statutory JWT (JSON Web Token) bearer authentication with HS256 algorithm.
- Multi-tier dependency injection for User, Optional User, and Admin clearance.
- Security Headers & Redis-backed rate limiting to defend against credential stuffing.
- Client-side token persistence via HTTP cookies (SameSite=Lax, max-age=86400) & localStorage.

3. BACKEND AUTHENTICATION MODULE (`backend/auth.py`)
--------------------------------------------------------------------------------

Functions & Helpers:
- `hash_password(password: str) -> str`:
  Encodes plaintext password to UTF-8 and hashes using `bcrypt.hashpw(password_bytes, bcrypt.gensalt())`.

- `verify_password(plain_password: str, hashed_password: str) -> bool`:
  Verifies input against stored bcrypt hash using `bcrypt.checkpw()`.

- `create_access_token(data: dict, expires_delta: Optional[timedelta]) -> str`:
  Encodes JWT with expiration payload (`exp = datetime.now(timezone.utc) + ACCESS_TOKEN_EXPIRE_MINUTES`)
  signed with `SECRET_KEY` via HS256 algorithm.

- `decode_access_token(token: str) -> dict`:
  Decodes JWT token and validates expiration. Raises HTTP 401 if token is invalid or expired.

FastAPI Dependency Injections:
- `get_current_user(credentials, db) -> User`:
  Extracts HTTP Bearer token from header, validates user ID, checks `is_active == True`, 
  and returns the SQLAlchemy User model instance. Raises HTTP 401 or 403 if invalid/deactivated.

- `get_current_user_optional(credentials, db) -> Optional[User]`:
  Optionally returns current user if valid bearer token exists, or `None` if unauthenticated.

- `get_admin_user(current_user) -> User`:
  Verifies `current_user.role == "admin"`. Raises HTTP 403 Forbidden if user lacks admin clearance.

4. BACKEND API ROUTER (`backend/routers/auth.py`)
--------------------------------------------------------------------------------
Prefix: `/api/auth` | Tag: `Authentication`

Endpoints:
1. `POST /api/auth/register` (Status Code: 201 Created)
   - Input Schema: `UserCreate` (`email`, `username`, `password`, `full_name`)
   - Output Schema: `TokenResponse` (`access_token`, `token_type`, `user`)
   - Logic:
     * Checks if email or username is already registered (HTTP 409 Conflict).
     * Hashes password with bcrypt.
     * Inserts new `User` record into database.
     * Generates and returns JWT access token and user payload.

2. `POST /api/auth/login` (Status Code: 200 OK)
   - Input Schema: `UserLogin` (`email`, `password`)
   - Output Schema: `TokenResponse` (`access_token`, `token_type`, `user`)
   - Logic:
     * Fetches user by email.
     * Verifies password against bcrypt hash (HTTP 401 if invalid).
     * Verifies account is active (HTTP 403 if deactivated).
     * Generates and returns fresh JWT access token.

3. `GET /api/auth/me` (Status Code: 200 OK)
   - Dependency: `get_current_user`
   - Output Schema: `UserResponse`
   - Returns full authenticated profile details for current token holder.

4. `PUT /api/auth/me` (Status Code: 200 OK)
   - Dependency: `get_current_user`
   - Input Schema: `UserUpdate` (`full_name`, `avatar_url`, `preferences`)
   - Output Schema: `UserResponse`
   - Updates current user's profile metadata and commits changes to SQLite/PostgreSQL.

6. SECURITY MIDDLEWARE & DEFENSE IN DEPTH
--------------------------------------------------------------------------------
- Rate Limiting (`middleware_security.py`):
  Redis-backed rate limiter limits failed authentication attempts on `/api/auth/login` 
  and `/api/auth/register` to prevent brute-force attacks.
- Security Headers (`middleware_security.py`):
  * `X-Frame-Options: DENY`
  * `X-Content-Type-Options: nosniff`
  * `Strict-Transport-Security: max-age=31536000; includeSubDomains`
  * `Content-Security-Policy`: Restricts unauthorized script execution.
- CORS Configuration:
  Configured in `main.py` allowing authenticated requests only from verified origins.
